Winlink Checkins Application - A Console Program to Tabulate Winlink Net Checkins
Description:
This application installs itself by default in C:\RMS Express\Global Folders\Messages but can be installed in any folder of your choosing. The net date range runs from midnight of the start date through midnight of the end date which are input when Checkins runs and includes the day before because of early checkins. It also asks for your callsign which is optional. If you provide the callsign, it will process message files in your personal folder ( C:\RMS Express\callsign\Messages). If you do not, it will run against messages in the folder where it was installed. You can get a copy of the installer at: https://drive.google.com/file/d/1lbN0yqKHRatzWRAnOHFdPWPKpwRZO2Wn/view?usp=sharing or https://github.com/KGBurton/Winlink_Checkins
Functionality:
The program will ask for a start date, an end date, and your callsign. It then looks in the specified/default folder for a file called “roster.txt” which is installed with the application. The first line in that file contains a unique keyword to identify the net (GLAWN) to be found in either the TO: field or the Message/Comment: field to work. It will scan the folder for MIME file types (the Winlink Messages) and process all files that fall between the start-1 and end dates, looking for key words to identify the net, the callsign of the sender, the location of the sender, and to identify the template, if used, in order to extract the checkin information. As it runs, some information is displayed in the console window to show status and events. The second line contains your callsign which is required if you want to edit any of the exported, customized messages. The third line contains the spreadsheet ID for the GLAWN Roster spreadsheet for programmatic update of the sheets. The fourth contains the name of the google credentials file required to use the api to access the spreadsheet. The fifth contains the roster list from the cell in red at the top of the spreadsheet. If there are new checkins, the roster.txt file will be updated. If the UpdateGoogleSheet method doesn't run, you can always update the spreadsheet manually using the checkins.txt file to add rows for new checkins in the current year and the New tabs. The string for the net checkins will need to be put at the top of the appropriate column for tabulation.

When it is finished, it will deposit files in the folder with the messages. 
	checkins.txt - contains a summary of all the records processed. The information in this file is used to populate the master spreadsheet to keep track of the weekly checkins and administrative information.
	checkins.csv”, a comma delimited file with each row containing the checkin data elementsThis can be reviewed to see the checkin basics and anything that was added as a comment. 
	mapfile.csv - This file can be imported into my.maps.google to create a map of the checkins (for which location information could be determined) with a pin for each, colored by band, and labeled with the callsign.
	Winlink_Import.xml - an import message file with all the checkins that had errors or warnings, formatted for easy import into Winlink for sending acknowledgements.
	Winlink_Import_Perfect.xml - an import message file with all the checkins that were perfect, formatted for easy import into Winlink for sending acknowledgements.
	GLAWN Additional Comments.txt - A text file with additional comments from the checkins.
